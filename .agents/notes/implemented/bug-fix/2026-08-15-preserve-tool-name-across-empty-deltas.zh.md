# Agent Note：跨空名称后续分片保留工具名

Status: implemented

[English](2026-08-15-preserve-tool-name-across-empty-deltas.md) | 中文

## 问题

OpenAI 兼容流可能在第一个分片提供有效工具名，却在后续参数分片重复发送 `function.name: ""`。DeepSeek 转换器把这个重复的空值当作权威值，因此结束工具调用分片和持久化 assistant 消息都带有空名称。即使模型在同一次调用中已经命名了一个已注册工具，工具分发仍会失败并报 `unknown tool ""`。

## 决策

DeepSeek 转换器只在 wire 分片包含非空字符串时更新进行中的工具调用名称。此前没有名称时，后续非空名称仍可补上；后续空值不能擦除已经确定的名称。对于畸形或不完整的提供方流，缺失名称仍保留现有的空名称兜底行为。

## 备选方案

- **在 `BlockAssembler` 中修复名称。** 不作为主要归属，因为提供方适配器负责从 wire 分片转换，而且已经发出了权威的 `block-end`；下游修复会掩盖适配器层的协议归一化缺陷。
- **出现空名称就拒绝整个流。** 否决，因为同一流中已经有有效名称和参数，不必丢弃完整的模型响应即可保留有效调用。
- **修改工具注册或执行查找。** 否决，因为注册表本身正确；失败原因是 assistant 消息中持久化了错误的空名称。

## 后果

工具调用可以跨过在只携带参数的分片中重复发送空名称的 gateway。真正没有任何工具名的调用仍按现有空名称兜底表示，并可能在分发阶段失败，从而区分可恢复的重复元数据和确实缺失的工具身份。

## 测试

DeepSeek 转换测试覆盖了首个分片带有效名称、后续参数分片带空名称的情况，并断言输出的增量和最终 `block-end` 都保留有效名称。
